# 可执行音色知识库

本库把“听感意图 → 合成机制 → 真实插件操作 → 可观察预期 → 验证 → 失败替代”串起来。主目标是 Sytrus，Surge XT 是可核对实现的对照，3xOsc 用于理解振荡器与立体声。资料访问日期为 **2026-11-01**；逐条出处、作者、版本、证据类别与局限见 [sources.json](../sources.json)。只保存摘要，不收录来源全文。

## 入口

- [Sytrus 操作与初始化](sytrus.md)：矩阵方向、FM/RM、波形/谐波、包络和本机 `.fst` 压缩证据。
- [听感目标与操作配方](perceptual-targets.md)：温暖、亮、空灵、厚、近、颗粒的歧义、参数动作和失败替代。
- [Surge XT 对照](surge-xt.md)：本机版本、init 边界、filter/AEG/FEG 与参数单位。
- [验证与记录](validation.md)：相同演奏、响度匹配、上下文、单声道、真实插件保存/重开/渲染。
- [recipes.json](recipes.json)：可供 Agent 顺序执行的结构化操作计划。`ui_percent` 是插件界面百分比，`seconds` 是设计目标，均不是宿主原始整数或归一化参数值。

## 证据的用途

| 类别 | 可以支持 | 不能支持 |
|---|---|---|
| 实验研究 | 指定材料、听众与任务中的知觉关系；说明何处存在歧义 | 把一个音频特征判为“温暖/好听”；直接认证本机配方 |
| 工程规范/官方实现 | 参数语义、矩阵方向、单位、路由和测量规则 | 审美优劣；未运行版本的兼容性 |
| 作者教程/实践经验 | 有出处的操作顺序、起始配方与排错方法 | 普适规律；未经验证的 CLI 参数映射 |
| 本库设计假设 | 一个明确、可回退、可以试听比较的候选 | 已达到用户听感要求 |

知识库中的具体配方数值是**工程起点和审美假设**，不是研究文献给出的最佳参数。研究 R01 区分了 airy/breathy、raspy/grainy/rough 与 harsh/noisy；三者有重叠特征，却不是同一种声音。R02 表明音色差异判断还受到声源类别/熟悉度影响。R03 说明组合、前景背景与融合关系需要在乐段里判断。因此，先保留用户的词和参考音，再选择一种解释，不能把词典变成单一目标函数。

## 执行约束

1. 使用真实 Sytrus / Surge XT 实例或其完整插件状态，不用自制 DSP 代替插件。先证明初始化、路由和单位，再执行配方。
2. “文档支持”“状态字段已定位”“写入后读回”“原生出音”“有人听过”是不同状态，分别记录。没有真实插件证据时不要升级状态。
3. 使用新工程副本和新输出文件；先保存起点和参数快照。所有未修改的私有字节继续保持原样。
4. 不把 UI 百分比、物理时间/Hz、宿主整数 `value_raw` 和 live API 的 `0..1` 混用。没有映射的控制保留为 GUI/待定位，不猜 ID 或偏移。
5. 每轮只改变一个机制或一个明确的小组，例如“FM 深度”或“滤波包络”；每个候选都补偿输出增益后比较。
6. 本次知识整理没有启动 FL Studio，没有操作用户工程，没有执行试听。当前工具链没有提供可据以判断音乐质量的听音能力；文中预期都不能写成已听到的结果。

本轮随后完成了 Default 家族的受控深层适配：FM/RM、ratio、SH、前32谐波与启用的四点音量包络均有原生保存、冷重开及音频证据，见[真实接口与验证](../sytrus.md)。这些证据不覆盖任意预设家族、全部谐波/相位、滤波矩阵或任意包络结构；其余机制仍应按未映射能力处理。
