## 盲测中发现并修复的问题

验收代理在冻结实现后自行创建两份输入，开发端未读取输入或开发验收脚本；失败后只收到最小症状，并用另外的自建工程定位。前四轮失败保留，未修改原定的音符、起始时间或静音判据。

- Basic 模板默认 Pattern 模式，非默认编号的编曲可能导出空白。新工程显式设为 Song 模式；渲染从同目录临时 Song 副本运行，保留源文件，并拒绝整体静音或明显截短的输出。
- FL 需要所有通道音符按起始时间排列。把替换记录追加到末尾，或只按通道排序，保存回读仍正确，但原生播放会漏音。所有 score 写入改为全局时间顺序，保留每条未修改记录的字节内容。
- Mixer 的文件段顺序是 Master、各 Insert、Current；原先错误旋转会使名称、静音、路由和效果器段错位，现与本机原生顺序对齐。
- `.fst` 的 wrapper 内含原宿主轨道和槽位。只移动插件事件会把效果器加载到原地址，实际影响其他声部。现在加载时重绑这两个地址；独立双声部原生导出确认只有目标声部产生混响尾音。
- 首次通过原判据后，附加 PCM 检查发现新曲默认全左。通道文件的声像以6400居中，Mixer以0居中；CLI现在统一用0居中，并在通道读写时转换。另一个自建三声部工程实际验证了居中时左右相等、最左时右侧为零、最右时左侧为零。
