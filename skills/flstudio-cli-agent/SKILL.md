# FL Studio CLI Agent

Use the installed `flstudio` CLI as the primary FL Studio interface. The aim is a
musically useful saved project and an audio artifact that can be inspected, not a
long transcript of tool calls.

## Start with a small view

Resolve the executable once in PowerShell:

```powershell
$fl = Join-Path $env:USERPROFILE '.local\bin\flstudio.exe'
& $fl --version
& $fl capabilities
```

For a saved project, begin with `project inspect --summary`. When the task spans
more than one turn, save a bounded context baseline:

```powershell
& $fl project snapshot --input song.flp --focus project --focus channels --budget 8000 --output state.json
```

Expand only the part needed for the next decision (`patterns`, `playlist`,
`mixer`, `automation`, or `arrangements`). After a milestone, query the same
focus with `--since state.json`. Treat `delta.equal=true` as “no change in the
comparable sections”; `delta.complete=false` means an omitted section is unknown,
not unchanged. Keep the baseline and the produced FLP beside the work session.

## Make changes as inspectable artifacts

- Prefer one explicit JSON request for one musical intention. Use `--dry-run` when
  the request is still being designed.
- Never overwrite a source or an existing output. Write a new FLP, then run
  `project validate` and, when useful, `project diff --before SOURCE --after OUTPUT`.
- Use saved-project editing for composition, channels, samples, Playlist, Mixer,
  Sytrus host controls, effect chains, and supported plugin profiles. Use `live`
  only for a running session; live writes require host readback and do not save.
- A result with `status=unknown` is unresolved. Do not repeat the same write blindly:
  read the current value, inspect `reason_code` and `rollback`, then choose a new
  action. `artifact_ready` means a file was produced and read back; it does not mean
  the user's open FL window changed.
- Automation is supported. For saved curves use `automation list`, `automation edit`,
  and `automation create` with a new FLP output. For live sampled automation use a
  private worker: `recording prepare` → `recording start` → `recording status` →
  `recording verify`, then `session save`. Plans target tempo, channel/Mixer level
  and pan, generator parameters, or effect parameters. A cancelled job preserves
  points already recorded and must be reported as partial until verified.
- Render non-silent work with the real FL engine and run `audio inspect` on the WAV.
  Use `peak_dbfs`, `rms_dbfs`, `channel_metrics`, `crest_factor`, duration, and the
  project timing check as evidence. Do not claim LUFS or true-peak compliance from
  these fields.

## Delegate plugin sound design

For timbre design, load `flstudio-sound-design`. Prepare an actual short excerpt
with `sound-design prepare`; its task contains the notes, tempo and context.
In the FL Studio DSH preset use `design_sound` to delegate the absolute task path
and output directory to the dedicated sound-design preset. Different children
need different task directories and private FL workers. Use `send_message` for
revisions and `list_agents` for status. The child does not inherit this chat.

Sytrus is the primary deep adapter: validated Default-family FM/RM, OP-to-filter,
FX/OUT/PAN, ratio, SH, first32 harmonics and enabled four-point VOL/CUT envelopes. Other
layouts require native UI/capture or supported host controls. Surge XT provides
a separate generic host path. Parameter names alone establish neither control
nor full plugin support.

Require complete FLP state, solo/context audio, save/cold-reopen evidence and a
small result.json generated by `sound-design report`; detailed catalogs and
metrics stay in the candidate observation files. Resume with `sound-design
status`, and expand only the next relevant operator using `sytrus design-inspect
--operator N --summary`. Apply with `sound-design apply` into a new file, undo with
`--undo`, then prepare a new task or branch under `parent` to continue. Without
listening, report signal evidence and provisional hypotheses only.

CLI1.2 adds scoped3xOsc, Maximus, WaveShaper/Delay3 and Edison/Slicex designs;
the specialist Skill's `producer-plugins.md` gives exact operations/limits.
`plugin design-inspect` observes saved fields; candidate/audition proves native
save/cold/audio. Do not substitute field enumeration for that evidence.

## Listen to the addressed musical object

With CLI1.3.0.dev0+, `audio preview` prepares a native saved copy for timbre,
Pattern, one Piano Roll (Pattern+channel), Mixer/Playlist track or song. Use an
owned `--session` to capture unsaved changes. In DSH both FL presets mount
`listen_audio`: send its ready preview manifest and a concrete question, or
compare matched candidate artifacts. This submits actual audio bytes to a
configured native audio model; attribute its observations to that listener.
The current conversation itself does not receive audio. Keep signal analysis
for mechanism checks and preserve subjective uncertainty.

Read [references/audio-listening.md](references/audio-listening.md) for scope
requests, occurrence timing, long-song windows/MP3, reuse and listening receipts.
For Sytrus performance maps, load the specialist Skill's expression/listening
reference. Default-family KEY/velocity/Mod X/Y on operator VOL and filter CUT
are now supported; other hidden modulation is not implied.

## Diagnose audio without hearing

Use `audio analyze --purpose overview|pitch|envelope|harmonics|delay`, choose the
question first, and write detailed observations with `--output`. Pitch assumes
one actual voice; confidence is periodicity, nulls remain unknown. Harmonic
comparison needs a stationary single note and aligned dry reference; first
exclude a simple gain change and compare unchanged repeats. Delay needs an
isolated pulse. Envelope timings come from actual PPQ/tempo/note-off, not raw
plugin units. Read `usability`, `reason_code` and `next_experiment` before making
a claim. Use the sound-design Skill's `analysis.md` for concrete request shapes.
Metrics diagnose mechanisms and possible context conflicts; they do not certify
musical quality. Without listening, return provisional choices and matched WAVs.

Native articulation is supported with note `slide/porta/muted/color`, readable
via `notes articulation`. Same-color Slide targets an already sounding voice;
its length is transition duration. Mono ordinary-note overlaps also glide;
`polyphony.slide_raw` is nonlinear0..1660, not milliseconds. VSTs do not
universally implement FL native Slide. Verify on a dry solo with pitch analysis.

## Musical decisions that generalize

- Establish the song's tempo, key or tonal center, section map, and reference target
  before filling every bar. Give the chorus a clear energy change through density,
  register, articulation, or arrangement rather than only louder faders.
- Build drums around a stable kick/snare relationship. Use velocity and small timing
  variation for groove; keep the sub transient and the kick fundamental from fighting
  in the same register. Avoid randomization that changes the pocket.
- Keep bass and kick readable in mono. Decide which element owns the lowest octave,
  trim unnecessary sub energy, and use sidechain or arrangement gaps only as much as
  the musical pulse needs.
- Write a small motif, then vary rhythm, register, articulation, or call-and-response
  across sections. Leave space for the lead and vocal; more notes are not more motion.
- Gain-stage before tone shaping. Use broad corrective EQ cuts, restrained boosts,
  short/long reverb sends with a shared space, and automation for transitions. Keep
  the master with useful headroom while arranging; judge the render rather than the
  mixer numbers alone.
- For Sytrus, decide the role first (sub, bass, pad, pluck, lead, texture), then set
  oscillator ratio/level, envelope, filter movement, unison, and stereo width in that
  order. Keep sub patches mono and use high-frequency width for contrast. Read the
  returned host controls; `null` is unknown, not zero.

## Long sessions

At each meaningful checkpoint record: source/output path, saved snapshot path,
the musical intent, the command used, and the validation result. Keep command
responses bounded with `--focus`, `--limit`, and `--budget`; request a detail view
only when it changes the next edit. Batch related file edits in one request, but
render and audio inspection after the composition or mix milestone, not after every
single note.

For a private live worker, use `session start` and pass the same `--session` file to
every live command. UI input is allowed only in a CLI-owned worker after a fresh
screenshot/receipt; `input_submitted` is not musical success until a getter or saved
artifact confirms it. Stop the owned worker when its checkpoint is saved.

Read [references/command-recipes.md](references/command-recipes.md) for compact
command sequences and [references/music-production.md](references/music-production.md)
when the request needs arrangement, sound-design, or mixing guidance.
